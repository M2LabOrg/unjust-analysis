# 04 -- Quality Assurance Strategy

## Why QA Matters Here

This analysis concerns racial justice and policing. Errors could undermine credibility or, worse, misrepresent the experience of affected communities. Every number must be defensible.

## QA Layers

### Layer 1: Data Validation (`qa/check_totals.R`)

**Against published GOV.UK totals:**

| Year | Published Total | Our Total | Match? |
|------|----------------|-----------|--------|
| 2022/23 | 547,002 | ? | -- |
| 2023/24 | ~405,000 | ? | -- |
| 2024/25 | ~403,000 | ? | -- |

- After cleaning, compare our aggregated totals to the headline figures in the GOV.UK statistical bulletin
- Document any differences (e.g., "our total is X because we exclude BTP and vehicle-only searches")
- Automated assertions that fail the pipeline if totals diverge by more than a defined threshold

### Layer 2: Rate Validation (`qa/check_rates.R`)

- Compare our calculated disparity ratios against GOV.UK published ratios
- Cross-check against Ethnicity Facts and Figures CSV downloads
- Validate that population denominators match Census 2021 published totals
- Check that rate per 1,000 calculations are correct (simple: count / population * 1000)

### Layer 3: Consistency Checks (`qa/check_consistency.R`)

- No negative counts
- Ethnicity categories are consistent across all years
- No duplicate rows
- Counts sum correctly across disaggregation levels (e.g., sum of forces = national total)
- Missing data proportions are documented per year
- All regions present in all years

### Layer 4: Model Diagnostics

- Poisson regression: check for overdispersion (dispersion parameter)
- Residual plots: no systematic patterns
- Influence diagnostics: no single observation drives the results
- Compare Poisson vs Negative Binomial fit
- Random Forest: OOB error rate, variable importance stability

### Layer 5: Reproducibility

- All analysis runs from a single `Makefile` or `build.sh`
- R package versions locked with `renv` (or Python with `requirements.txt`)
- Raw data is either included in repo or downloaded via script with checksums
- Every figure in the report is generated by code, not manually created
- The QA report (`qa/qa_report.qmd`) is rendered as part of the build and included as an appendix or linked from the main report

### Layer 6: Peer Review Checklist

Before publication, manually verify:

- [ ] All headline numbers in the report match the analysis output
- [ ] All citations are correct and up to date
- [ ] The methodology section accurately describes what the code does
- [ ] The dashboard numbers match the report numbers
- [ ] No personally identifiable information is exposed
- [ ] The language is respectful and accurate regarding affected communities
